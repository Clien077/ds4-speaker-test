测试 PlayStation DualShock 4 手柄的**内置扬声器（和 3.5mm 耳机口）**是否正常工作，
**支持任意自定义测试音频**（wav / mp3 / flac / ogg / m4a…），也内置扫频、噪声、声道点名等标准测试信号。

工具同时提供两条完全不同的通路，因为 **DS4 的内置喇叭在 Windows 里根本没有音频设备**：

| 通路 | 说明 | 命令 |
|---|---|---|
| **蓝牙 HID + SBC**（真·内置喇叭） | 按 PS4 的私有协议，把 SBC 音频塞进 HID 输出报告直接发给手柄 | `--bt` |
| Windows 音频端点（3.5mm 耳机口） | 手柄的 USB 音频类 / 蓝牙音频端点，只驱动耳机口，不驱动内置喇叭 | 默认 |

## 1. 为什么不能用 Windows 音频设备测内置喇叭

- Windows 上那个 `耳机 / 麦克风 (Wireless Controller)` 是 **USB 音频类（UAC）**，走的是手柄的
  **3.5mm 耳机口**；蓝牙下如果只配成 HID 设备，连这些端点都不会出现。
- **DS4（DualShock 4）没有内置麦克风**（有麦克风阵列的是 PS5 的 DualSense）；那个
  `麦克风 (…Wireless Controller)` 是耳机口上的耳麦麦克风，不插带麦耳机必然是静音。
- **内置喇叭**由 PS4 通过蓝牙 HID 输出报告里塞 **SBC 编码音频**驱动（私有协议，
  不是 A2DP）。参考实现：[nefarius/DS4AudioStreamer](https://github.com/nefarius/DS4AudioStreamer)、
  [ds4drv #76](https://github.com/chrippa/ds4drv/issues/76) 与其
  [play.py](https://gist.github.com/a1ien/e8a82f71c13ae54f886fbf94f0606073)。

### 从原始协议里挖出来的关键参数（本工具已全部对齐并实测通过）

| 项目 | 值 | 说明 |
|---|---|---|
| **0x11 控制报告** | 78 字节，**必须先发** | 不发这条内置喇叭永远没声音 |
| ├ `[2]` | **0x20** = `audio_control` | **启用音频路径**。这里填 0xA2 就完全没声音（0xA2 只属于音频报告的第 3 字节） |
| ├ `[21..25]` | `0x43,0x43,0x00,音量%,0x85` | 音量是**百分比**（0-100），后面还必须跟 `0x85` |
| └ `[74..77]` | CRC32（种子 0xA2，覆盖前 74 字节） | 手写时容易放错位置 |
| **音频报告** | **0x17**（4 帧/462B）或 **0x14**（2 帧/270B） | 4 帧优先，剩 1～3 帧时用 0x14 |
| ├ `[2]` | **0xA0** | 用 0xA2 无声 |
| ├ `[5]` | **0x02** = 内置扬声器，`0x24` = 3.5mm 耳机口 | 来自 PS4 真机抓包 |
| └ CRC32 | 放在**该报告真实长度的末尾** | 0x17→`[458:462]`，0x14→`[266:270]` |
| **写入长度** | **547 字节**（HID 集合最大输出报告长度） | 只写 462/270 字节会被驱动拒绝/手柄丢弃；必须补零写满 |
| SBC 编码 | 32 kHz / 2 声道，ffmpeg 默认参数（8 子带 16 块 联合立体声 比特池 26 → **65 字节帧**）| 帧长由帧头决定，手柄按帧头解析 |
| 握手 | 先发一版带马达的 0x11（手柄震一下），再发正式版 | 震一下 = HID 通道 + 音频路径已就绪 |
| 节奏 | 每 16 ms 发一条 4 帧报告（= 250 帧/秒） | 与实时播放对齐 |

> 以上参数由你的 `F:\Program Files (x86)\DS4扬声器测试`（PS4 抓包 + Linux `hid-playstation.c` + Unity 三处互证）
> 校准，并已用**麦克风回采客观复核**：参考工具播放窗口 RMS -37.8 dBFS / 底噪 -65.3 dBFS（**+27.6 dB**），
> 本工具改用上述参数后播放窗口 RMS ≈ -22 dBFS，频谱相似度 0.88~0.9。

## 2. 快速开始

```bat
:: 双击 run.bat 打开图形界面，或者：
python ds4_speaker_test.py                       :: 图形界面（默认走蓝牙内置喇叭）
python ds4_speaker_test.py --bt-list             :: 查看手柄 HID 接口及连接方式（蓝牙/USB）
python ds4_speaker_test.py --bt-selftest         :: 蓝牙通路离线自检（不发声、不发送）
python ds4_speaker_test.py --bt-control-test     :: 用灯条+震动验证 HID 通路（肉眼可确认）

:: 蓝牙内置喇叭（手柄必须蓝牙连接）
python ds4_speaker_test.py --bt --signal sweep
python ds4_speaker_test.py --bt --file D:\music\test.mp3
python ds4_speaker_test.py --bt --loopback-test --signal tone --duration 3

:: Windows 音频端点（3.5mm 耳机口）
python ds4_speaker_test.py --list
python ds4_speaker_test.py --signal sweep --device 26
python ds4_speaker_test.py --loopback-test --file test.flac
python ds4_speaker_test.py --selftest            :: 离线自检
```

依赖：`numpy` + `sounddevice` + `pywinusb`（本机已装）。
非 WAV 解码与 SBC 编码用 ffmpeg —— 优先用 `imageio-ffmpeg` 自带的 ffmpeg。

## 3. 蓝牙通路为什么需要蓝牙连接

内置喇叭的音频只能通过**蓝牙 HID** 送给手柄（USB 连接下这条通路不通）。

- 手柄长按 **Share + PS** 键进入配对，在 Windows 蓝牙里添加 `Wireless Controller`；
- 用 `--bt-list` 确认显示的是 **BT**；
- 如果 DS4Windows 正在运行，建议先退出，避免它抢占 HID 设备。

## 4. 图形界面

1. **输出通路与设备**：选「蓝牙内置扬声器（HID + SBC）」或「Windows 音频端点」；
   蓝牙模式下可选手柄 HID 的**报告通路字节**（默认 0x24，实测可用）。
2. **测试音频**：内置信号，或**自定义音频文件**（浏览选择，可设起始位置与时长）。
3. **播放设置**：音量（-40 ~ +20 dB）、声道路由（双声道 / 仅左 / 仅右）、循环播放。
4. **实时电平表**：蓝牙模式显示推流进度；音频端点模式显示每声道峰值与削波计数。
5. **回环自检**：播放一遍 → 用麦克风录回来 → 自动判定，并可把录音存成 WAV。

## 5. 内置测试信号

| 名称 | 用途 |
|---|---|
| `tone` | 单音（默认 1 kHz，`--freq` 可改）——最简单的"有没有声音" |
| `sweep` | 20 Hz → 20 kHz 对数扫频：听破音、杂音、频响断层 |
| `sweep_speech` | 200 Hz → 6 kHz：人声频段，判断音量与清晰度 |
| `white` / `pink` | 白噪声 / 粉噪声：全频段压力测试 |
| `channels` | 左 → 右 → 全部：左右声道点名（测耳机口） |
| `polarity` | 同相 / 反相：低频相位检查 |
| `dtmf` | 双音多频 1-0：固定频率组合，快速判断频响失真 |
| `silence` | 静音：只验证链路能否打开（不发声） |
| `all` | 完整测试序列（约 32 秒，依次播放全部项目） |

## 7. 回环自检（自动判定）

流程：**先录 0.5 秒 → 播放测试音频 → 再录 1 秒 → 分析**。

判定依据（只取"应该在出声"的那段时间，并对比推流前后的底噪）：

1. **信噪比**：播放窗口比底噪高不到 6 dB → 直接判 `SILENT`（这一步很关键：
   频谱相似度对"只有底噪"的录音没有鉴别力，曾经因此误报过 PASS）；
2. **拾音电平**：峰值低于 -50 dBFS 判 `SILENT`；
3. **频谱相似度**（80 Hz ~ 8 kHz 余弦相似度）与**包络相关**（有起伏的信号还能估延迟）。

| 判定 | 含义 |
|---|---|
| `PASS` | 正常出声，且与测试音频高度一致 |
| `WEAK` | 有声但匹配度偏低（音量小 / 失真 / 底噪大） |
| `CLIPPED` | 严重削波，音量过大 |
| `SILENT` | 几乎没出声（音量太低 / 通路字节不对 / 麦克风选错） |
| `UNCLEAR` | 录到声音但不像测试音频（多半只是环境噪声） |

退出码：`0` = PASS，`1` = WEAK/UNCLEAR，`2` = SILENT/CLIPPED。

**DS4 内置喇叭本身音量非常小**，请在安静环境把手柄贴近耳朵或用麦克风凑到 10 cm 内验证。

## 8. 音频断续（卡顿）怎么处理

DS4 的蓝牙 HID 音频通路**天生会偶尔掉音**：当年把它逆向出来的作者（[ds4drv #76](https://github.com/chrippa/ds4drv/issues/76)、
[pvsm 那篇文章](https://www.pvsm.ru/python/124992)）都写下"声音有周期性小卡顿，没搞清原因"，一直没人解决。

本工具做了三件事削掉大部分卡顿：

| 措施 | 说明 |
|---|---|
| 预打包全部报告 | 推流时只做"等待 + 写入"，Python 侧每包耗时从 0.05 ms 降到 0.01 ms，不再有 GC 抖动 |
| 预灌缓冲 `--bt-lead`（默认 6 条 ≈ 96 ms） | 开播瞬间连发若干条把手柄抖动缓冲垫起来，吸收蓝牙链路抖动 |
| 周期性控制刷新 `--bt-control-every`（默认 20） | PS4 真机就是把控制状态混在音频流里持续刷新（0x15/0x19），完全不刷新时手柄音频路径偶尔会"饿" |

**实测（同一段 1 kHz 稳定单音，麦克风回采统计掉音缺口）**：

| 实现 | ≥20 ms 缺口时长占比 |
|---|---|
| 参考工具（你机器上那个） | **20.1%**（最长单次 1.49 秒） |
| 本工具 `lead=0` | 4.1% |
| **本工具 `lead=6`（默认）** | **3.5%** |

主机侧时序几乎是理想的（发送间隔 16.000 ms、写入 0.2 ms、迟到 0 条），残余掉音来自蓝牙链路本身。若仍觉得卡：

1. `--bt-lead 12` 或 `--bt-lead 20`（加大预灌，代价是延迟略增）；
2. `--bt-speed 1.02`（慢慢把缓冲垫厚；太高会溢出反而更卡）；
3. `--bt-frames 2`（改用 270 字节小报告，掉一次只丢 8 ms，卡顿感更轻）；
4. **减少 2.4 GHz 干扰**：蓝牙和 WiFi/无线鼠标共用 2.4 GHz 频段 —— 把 2.4G 无线接收器插到别的 USB 口（或远离手柄）、WiFi 换 5 GHz，效果通常最明显；
5. 手柄离电脑近一点，中间别挡东西。

图形界面里也有对应的「预灌缓冲 / 送流速率 / 控制刷新」输入框，可以边听边调。

## 9. 打包成 EXE

双击 `build_exe.bat` 即可（自动检查依赖 → 打包 → 整理到 `release\`）。产物：

| 文件 | 用途 |
|---|---|
| `release\DS4扬声器测试\DS4扬声器测试.exe` | **推荐**：文件夹版，双击即用。启动快（约 1 秒），**运行时不解压任何文件**，任何启动方式都不会出错 |
| `release\DS4扬声器测试(单文件).exe` | 单文件版，52 MB 好搬运；启动时把自己解压到**自身所在目录**（`--runtime-tmpdir .`） |
| `release\DS4扬声器测试-CLI.exe` | 命令行单文件版，输出可重定向/写脚本 |
| `release\使用说明.txt` | 给最终用户看的简明说明 |

EXE 里已打包 ffmpeg（imageio-ffmpeg）、PortAudio（sounddevice）、pywinusb 与 tkinter，目标机器**不需要装 Python 或任何依赖**。

### 为什么主推"文件夹版"

单文件版每次启动都要把 52 MB 解压到临时目录，这一步有两个常见坑：

1. **杀软拦截**解压过程；
2. **完整性级别限制**：如果 exe 是从聊天窗口的"文件卡片"、或被沙箱化的环境启动的，它会带着**低完整性令牌**运行，
   而 `%TEMP%` 是中等完整性 —— Windows 的强制完整性控制（MIC）**禁止低完整性进程向上写**，
   于是报 `Could not create temporary directory!`（解压目录的 ACL 会留下
   `Mandatory Label\Low Mandatory Level:(NW)` 的痕迹）。

文件夹版**运行时不创建任何目录**，所以完全不受这两点影响。真想用单文件版时，请从**普通的资源管理器窗口**双击，
不要在聊天窗口的文件卡片里点。

## 10. 常见问题

**蓝牙推流没声音？**
1. 先跑 `--bt-control-test`：灯条变绿 + 震动 = HID 通路正常；都没反应说明报告没被接受
   （多半是别的程序占了 HID，或手柄不是蓝牙连接）；
2. 换通路字节：`--bt-path 0x24`（耳机口）/ `0x00` / `0x03`；
3. 确认手柄音量，`--bt-volume 255`（默认已最大）；
4. DS4 小喇叭音量有限，请贴耳确认；插一副耳机到手柄耳机口对比，可区分"通路问题"和"喇叭问题"。

**USB 连接时能用蓝牙通路吗？** 不能，内置喇叭只走蓝牙；`--bt-list` 会提示当前是 USB。

**WASAPI 独占打不开？** 独占要求采样率与设备原生格式一致，去掉勾选或指定 `--samplerate`。
